① Tab toggle: Uses role="tablist" / role="tab" / aria-selected="true" for WCAG 2.1 (4.1.2). Active tab has visible blue underline + bold weight for sighted users.
② Password show/hide: Toggle button has aria-label="Show password" / "Hide password" toggled dynamically (WCAG 1.3.5). Input type flips between "password" and "text".
③ Forgot password: Link is visible but links to post-MVP feature — shows toast notification "Feature coming soon" at click. Badge makes post-MVP status clear during stakeholder review.
④ Post-login: JWT stored in httpOnly cookie (XSS-safe). Redirect to previous page via ?next= query param, or default to /.

Error banner: Uses role="alert" and aria-live="assertive" so screen readers announce the error immediately (WCAG 4.1.3). Both email and password fields get .error class — no hint about which field is wrong (prevents credential enumeration).
Rate limiting: After 5 consecutive failures from the same IP/email, backend returns 429 — UI shows "Too many attempts. Please wait 15 minutes." variant of this error banner. Handled by AWS WAF rate rule.

Inline field errors: Each error message is linked to its field via aria-describedby and field marked aria-invalid="true". Error text announced by screen readers when field loses focus (WCAG 3.3.1).
Disabled submit: CTA uses disabled attribute + cursor-not-allowed styling. aria-disabled="true" ensures screen readers announce unavailability. Re-enables only when all required fields pass client-side validation.

Loading state: All form inputs and the submit button are disabled during the request to prevent duplicate submissions. role="status" + aria-live="polite" on the button wrapper announces "Signing in..." to screen readers (WCAG 4.1.3).
Timeout handling: If POST /api/v1/auth/login/ does not respond within 10s, the loading state exits and State 3 (error banner) is shown with message "Request timed out — please try again."
