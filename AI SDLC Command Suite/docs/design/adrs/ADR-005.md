# ADR-005: AWS ECS Fargate Deployment Platform

**Status:** Accepted
**Date:** 2026-05-14
**Deciders:** Full-stack Lead, Backend Developer

---

## Context

ShopNest requires a production deployment platform that:
1. Hosts three services: Django API, Celery Worker, Next.js Frontend
2. Satisfies NFR-REL-001 (99.9% uptime — requires Multi-AZ redundancy)
3. Satisfies NFR-PORT-002 (zero EC2 instance management — no server patching)
4. Satisfies NFR-PE-006 (≥1,000 concurrent users — requires auto-scaling)
5. Fits within CON-001 ($2,000/month AWS budget)
6. Is operable by a 3-person team with no dedicated DevOps (CON-003)

The platform must support:
- Horizontal auto-scaling triggered by CPU utilization
- Zero-downtime rolling deploys
- Per-service health checks
- Docker OCI container execution (NFR-PORT-001)
- TLS termination + HTTPS enforcement
- Network isolation (3-tier subnet: public ALB / private app / isolated data)

---

## Decision

**AWS ECS (Elastic Container Service) with Fargate launch type in ap-south-1 (Mumbai).**

Three ECS services:
1. **shopnest-api**: Django + Gunicorn (1 vCPU / 2GB RAM, min 2 / max 10 tasks)
2. **shopnest-celery**: Celery Worker (0.5 vCPU / 1GB RAM, min 1 / max 4 tasks)
3. **shopnest-frontend**: Next.js (0.5 vCPU / 1GB RAM, min 2 / max 8 tasks)

Supporting infrastructure:
- Application Load Balancer (ALB) in public subnet — HTTPS termination, path routing, health checks
- AWS WAF attached to ALB — rate limiting, SQLi/XSS rules, GeoIP India-only restriction
- AWS ACM certificate — auto-renewal HTTPS for `shopnest.in` and `api.shopnest.in`
- VPC with 3-tier subnet isolation (public / private / isolated)
- AWS CloudWatch — structured log aggregation, metric alarms, auto-scale triggers
- AWS ECR — private container registry with image scanning
- AWS Secrets Manager — all credentials fetched at task startup

---

## Rationale

**ECS Fargate over EC2 Auto Scaling (NFR-PORT-002):** Fargate is serverless containers — AWS manages the underlying EC2 fleet, OS patching, and instance lifecycle. ShopNest never touches a server. For a 3-person team with no DevOps, this eliminates the operational burden of AMI management, security patching, and instance monitoring. NFR-PORT-002 explicitly requires "No EC2 instance management."

**ECS over EKS Kubernetes (CON-001, CON-003):** An EKS cluster costs ~$200/month for the control plane alone before any worker nodes — consuming 10% of the $2,000/month budget for a cluster management layer with no user-facing value. ECS Fargate has no cluster management fee; cost is per vCPU-hour and GB-hour of running tasks. Additionally, Kubernetes requires operational expertise that exceeds a 3-person team's capacity to develop alongside feature delivery.

**ALB path routing:** A single ALB routes `/* → Next.js` and `/api/v1/* → Django API`, reducing the number of load balancers to 1 (saves ~$20/month vs. separate ALBs). TLS is terminated at the ALB, so all inter-service traffic within the VPC is HTTP (within VPC security groups).

**Multi-AZ deployment (NFR-REL-001):** ECS tasks are distributed across ap-south-1a and ap-south-1b. With min 2 tasks per service, one AZ failure leaves the other AZ serving traffic through the ALB. RDS Multi-AZ provides < 60s automatic failover. Together, these enable ≥99.9% monthly uptime.

**ap-south-1 (Mumbai) region:** DPDPA 2023 requires Indian user data to reside in India. AWS Mumbai is the closest AWS region to ShopNest's target users, providing the lowest latency for API calls and database access. CloudFront edge locations in Mumbai, Delhi, and Chennai serve images.

**WAF GeoIP restriction:** CON-004 (India-only) means blocking non-Indian IPs at the WAF layer reduces attack surface and prevents abuse from outside India. This is implemented as a WAF GeoIP rule, not at the application layer.

## Alternatives Considered

| Option | Pros | Cons | Why Rejected |
|--------|------|------|-------------|
| EC2 Auto Scaling | More control; can right-size instances precisely; cheaper per vCPU-hour | OS patching, AMI management, instance monitoring required; violates NFR-PORT-002; significant DevOps time for 3-person team | NFR-PORT-002 violation; team capacity |
| AWS EKS (Kubernetes) | Industry standard; ecosystem; future portability | $200+/month cluster fee (10% of budget); Kubernetes learning curve; overkill for 3 services | CON-001 budget; CON-003 team capacity |
| AWS Lambda + API Gateway | Zero servers; auto-scaling to millions; pay-per-invocation | 15-minute max execution blocks Celery payout job; cold starts violate NFR-PE-001 (P95 < 200ms); complex local dev | Execution time limit; cold start latency |
| AWS Elastic Beanstalk | Simple PaaS; EC2-backed | Still manages EC2 AMIs under the hood; less control than ECS; harder to integrate multi-container; not fully serverless | EC2 management overhead; less flexible than ECS |
| GCP Cloud Run | Serverless containers; auto-scaling | Not AWS — cross-cloud adds cost and complexity; team has AWS knowledge; GCP data residency in India less mature | Platform mismatch; team knowledge |
| Render / Railway (PaaS) | Simplest deployment; no AWS knowledge needed | Vendor lock-in; not enterprise-grade; not available in India region; no DPDPA data residency guarantee | Compliance risk; feature limitations |

## Consequences

**Positive:**
- Zero server management — 3-person team focuses entirely on feature delivery
- Auto-scaling handles traffic spikes (e.g., promotional events) automatically
- Rolling deploys with health checks guarantee zero-downtime updates
- ECS task definitions are JSON — 100% infrastructure as code (NFR-MAINT-006)
- ECR image scanning catches known CVEs before deployment
- CloudWatch integration provides structured logging, metrics, and alarms without additional tools

**Negative (accepted):**
- ECS Fargate has a ~10-second cold start when scaling from 0 to 1 task — mitigated by maintaining min 2 tasks always
- Fargate costs slightly more per vCPU-hour than EC2 Reserved Instances (~30% premium) — the operational time saved for a 3-person team far exceeds the cost difference
- ECS task definition updates require ECS-specific knowledge — documented in infra/ directory and runbook

**Estimated monthly cost (at 100 sellers, ~1,000 users):**
| Component | Estimated Cost (USD/month) |
|-----------|--------------------------|
| ECS Fargate — Django API (2 tasks avg) | ~$35 |
| ECS Fargate — Celery Worker (1 task avg) | ~$9 |
| ECS Fargate — Next.js Frontend (2 tasks avg) | ~$18 |
| RDS db.t3.small Multi-AZ | ~$70 |
| ElastiCache cache.t3.micro | ~$14 |
| ALB | ~$20 |
| AWS WAF | ~$10 |
| CloudFront (images + assets) | ~$15 |
| S3 (images + invoices) | ~$5 |
| SES (10,000 emails/month) | ~$1 |
| Secrets Manager | ~$3 |
| CloudWatch (logs + metrics) | ~$15 |
| ECR | ~$5 |
| **Total** | **~$220/month** |

Well within CON-001 ($2,000/month = ~₹1,66,000/month). Leaves significant headroom for traffic growth and auto-scaling.
